# 金额输入支持 4 位小数（万元 = 精确到元）

日期：2026-10-15

## 背景

金额输入框现在只能输入整数「万元」，但限制并不在输入框本身——`setPrice` / `setLoan` 都原样存下了用户输入的小数。
真正吃掉精度的是 `src/stores/loan.ts` 的 `r1()`：它把每一处万元金额统一按 **0.1 万 = 1000 元** 取整，
贷款总额、首付、组合贷拆分、以及参与摊还计算的 `P` 全都过这道闸门。
所以在输入框里敲 `150.1234`，计算结果仍按 `150.1` 万走。

目标：让金额精确到 **1 元**。

## 精度模型：为什么保留「万元」而不是改成「元」

`0.0001 万 = 1 元`。因此「万元保留 4 位小数」与「精确到元」是**同一件事**，
且换算到元之后永远是整数，不会残留浮点尾数。

沿用万元单位的好处：

- 「150.1234 万」比「1,501,234 元」更贴近日常说法，读数更短
- 三个金额滑块的量程不必从 1–3000 万放大到 10000–30000000 元

这条换算关系会写进代码注释，避免以后有人以为「4 位小数」是随手定的数字。

## 范围

### 纳入

| 输入框 | 单位 | 现状 | 目标 |
| --- | --- | --- | --- |
| 房屋总价 | 万 | 计算时按 0.1 万取整 | 精确到元 |
| 贷款金额 / 贷款总额 | 万 | 同上 | 精确到元 |
| 组合贷 · 公积金部分 | 万 | 同上 | 精确到元 |
| 组合贷 · 商贷部分 | 万 | 同上 | 精确到元 |

外加：上述每个输入框旁实时回显折算后的元金额。

### 明确不做

- **贷款年限不动**。商业贷款 40 年 / 公积金 30 年 / 组合贷 30 年，维持 2026-09-11
  `2026-09-11-commercial-loan-40-years-design.md` 的结论，本次不涉及。
- **每月公积金金额（元）保持整数**。它的单位已经是元，4 位小数等于 0.0001 元，没有意义。
- 首付比例（%）、年利率（%）不是金额，维持现状。
- **滑块 `step` 维持 1 万**。滑块负责粗调、数字框负责精调，4 位小数在滑块上没有意义。
- `fmt` / `money`（结果区与还款计划表）维持四舍五入到整元。金额精确到元之后，这个取整已是恒等变换。

## 改动清单

### `src/stores/loan.ts`

1. `r1` 改名并改精度为 `r4`：`Math.round(v * 10000) / 10000`。
   全部 14 处调用点（12 行）同步替换：`buildLoanRows`、`loanTotalWan`、`downWan`、
   `fundComm`、`summary`、`setFundWan`、`setCommWan`。
2. `setPrice` / `setLoan` 增加 `r4` 包裹：state 里的万元值恒为「不超过 4 位小数」，第 5 位起自动舍入。
3. 新增导出 `wan(v: number): string`：万元金额的**显示**格式化——最多 4 位小数、自动去掉末尾 0、保留千分位。
4. `typeLine` / `summaryItems` 里裸插值的 `${fc.fund}` / `${fc.comm}` 改用 `wan()`，
   否则会渲染出 `60.0001万` 这种。
   （`copyText` 原本就用 `fmt()` 输出元金额，无需改动。）

### `src/components/InputPanel.vue`

1. **`makeNumHandler` 的回写策略——本次真正的根因，实施中才定位到**。
   原实现在每次 `input` 事件后无条件 `el.value = String(getVal())`。
   用户敲 `150` 再敲 `.` 时，浏览器把 `<input type=number>` 的 `.value` 报成 `150`
   （小数点只存在于原始文本里），于是 `parseFloat` 得到 150、回写 `"150"`，
   **刚敲下的小数点当场被抹掉**——金额框根本输不进小数。
   改为只在「钳制真的改动了数值」（`typed !== Number(next)`）时才回写：
   中间态 `150.` 与末尾多余的 0（`0.50`）都原样保留。
   `onBlur` 则始终回写，把 `150.` 归一化成 `150`。
2. 5 处金额数字框的 `step="1"` → `step="any"`：解除 HTML 的 step 校验，
   避免 `150.1234` 被判为 `:invalid`（范围钳制由 setter 负责，不依赖 step）。
3. 6 处万元读数字的 `toLocaleString('zh-CN')` 改用 `wan()`
   （房屋总价 L120、首付 L139、贷款金额 L170、贷款金额只读 L191、组合贷总额 L203、组合贷商贷部分 L243；
   每月公积金金额的读数字与快捷按钮 L393 / L409 是整数，不动）。
   `toLocaleString` 默认 `maximumFractionDigits` 是 **3**，当前就会把 `105.0864` 显示成 `105.086`
   ——这是既有 bug，本次一并修掉。
4. 补元回显（`class="mono-sub"`，形如 `≈ ¥1,501,234`）：
   - 房屋总价：`field-foot` 内新增一项
   - 组合贷：`combo-inputs` 下新增一行（跨两列，样式 `.combo-yuan`），同时给出公积金与商贷两部分的元金额
   - 贷款金额 / 贷款总额 / 首付：已有回显，不动

### `src/style.css`

- 新增 `.combo-yuan{ grid-column: 1 / -1; }`，让组合贷的元回显行跨满 `.combo-row` 的两列。

## 实施中发现的既有 bug

两个都经浏览器实测确认在改动前的 `HEAD` 上就已存在，与本次精度改造无关。

1. **输入框敲不进小数点**（上述第 1 条）。这才是「金额输入框不支持小数」的**真正原因**——
   不是精度被取整，而是小数点根本进不去。已一并修复。
2. **切换到组合贷后，两个利率输入框一片空白**。
   `watch(() => store.loanType, syncRateInputs)` 用默认的 `flush: 'pre'`，
   回调在组件重渲染**之前**执行，此时 `v-else` 分支（组合贷的两个利率框）尚未渲染，
   模板 ref 仍是 `null`，同步落空。加 `{ flush: 'post' }` 修复。
   注意 `store` 里的利率值一直是正确的，只有输入框的显示值没跟上。

### 不受影响

`ResultPanel.vue`、`AmortizationTable.vue`、`persist.ts`
（`.field-foot` 已是 `flex-wrap: wrap`，`.combo-row` 是 grid，新增一行可自然容纳）。

## 边界

| 场景 | 行为 |
| --- | --- |
| 输入超过 4 位小数（如 `150.12345`） | setter 舍入为 `150.1235`，并立即回显到输入框 |
| 组合贷两部分与总额自洽 | 商贷 = `r4(总额 − 公积金)`，公积金 = `r4(总额 − 商贷)`，三者在 4 位小数下严格相加 |
| 旧 localStorage 数据 | 历史值小数位 ≤ 1，天然落在新范围内，无需迁移 |
| 按总价模式 | 贷款额 = `r4(总价 × (1 − 首付比例))`，首付 = `r4(总价 − 贷款额)` |

   - `summary.P` 等于 `loanTotalWan × 10000`，为整元
   - 每月公积金金额仍为整数（回归保护）
2. `npm run typecheck`、`npm test`、`npm run build` 全部通过
3. 浏览器实跑（Chromium，19 项断言全过）：
